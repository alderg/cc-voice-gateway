2. Gateway

The voice endpoint listens on 127.0.0.1 at this port; the tunnel or proxy forwards to it.

With several gateways, each a connector in the Claude app, every answer of the connector starts with "Gateway <name> (Mac): active" or "inactive", so that the voice assistant uses the right one. Empty: this computer's name.

On standby, for a test install for example, the connector says it is inactive and passes no request on, so that the voice assistant uses another one.

Removed in the Claude app, the connector is detected and the gateway says so once on Telegram, then stops its workers and stays quiet: no reminders, no alerts. A new sign-in with a pairing code switches it on again, queue and open decisions as they were.

Every git repository directly in this folder gets a worker (on this computer, without Docker).

How many workers may run at once, in all repositories together: the limit that protects your subscription. Every run of a repository counts.

How many of them in one repository at once. 1, the default: one after the other. More: the first runs in the checkout, every further one in a git worktree of its own, and the controller decides per task whether it can run next to the others. Both limits apply at once in a running gateway, without a restart.

A run is stopped after this; 360 is six hours. 0: no time limit.

Ready for review, automatic reviews start at once. A draft usually gets them only once it is marked ready, and cannot be merged before.

New reviews and comments that ask for changes, from the repository's owner, members and collaborators or from Copilot and the Claude app, get a fix by the worker that pushed the pull request, round after round as the reviews run again; the controller tells you as news. Anyone else's comments start nothing.

After that many, the controller tells you, and a further fix takes your word, until you have something done for that pull request again. 3 by default.

The rare approval the controller needs is read out in the car, and with Telegram set up (section 4) it goes to your chat at once too. So do those of its helper agents in the background, also the ones it starts with a name, which Claude Code shows only at the terminal: its approval hook hands them over.

An approval for a file write, such as a project's memory file, also offers to allow all such writes of the same helper in the same folder for a while: "once, no, or all such for 20 minutes?" Never the shell, settings, hooks, CLAUDE.md, .git or a merge, which keep asking. "Freigaben zurücknehmen" by voice, or /revoke in Telegram, ends them, and so do the kill switch and a standby.

How long one holds when you name no minutes: 20 by default, 5 to 120.

Follow the controller as "Voice controller" at claude.ai/code or in the Claude app's Code tab: read along, type to it, answer its approvals. Only the controller: Remote Control connects interactive sessions, not the workers' headless runs. Needs Claude Code signed in with claude.ai here; on Team and Enterprise an Owner turns it on first. Whoever is signed in to that account can then steer the controller; typed words start no worker, only voice requests do.

Confined: it answers, hands work to the workers and reads pull request status; nothing else. The other two levels widen what a voice request can do on this computer.

What locks the gateway and stops every worker. Manual: "emergency stop" by voice, /stop on Telegram and the controller's alarm. Automatic: also fixed rules on the workers' runs: a write outside the repository or unusually many changes. The first two new files a run writes outside, in a place that is not sensitive, go to quarantine instead, with a warning on Telegram. A folder one repository's workers really use outside it, such as a service's data folder, can be granted to that repository with VOICE_GW_PATH_GRANTS in the settings file (README, path grants). You unlock it at this computer with node scripts/unlock.mjs, or with Telegram set up (section 4) in voice mode: say "unlock", and read out the PIN that comes to your Telegram chat. Three wrong PINs leave only the computer for that lock.

The public endpoint is then only up while you use it. The gateway says on Telegram when it turned the Funnel off; /funnel on or "keep alive" there turns it on again, within about two minutes. Without Telegram only at the computer: scripts/funnel.sh start.

90 covers a break in a long drive.

The public HTTPS port; Funnel allows only these three. Keep 443 for claude.ai's connector: it did not connect to 8443 in our test, although Funnel serves it publicly.

3. Models

The controller answers by voice, so speed counts: a smaller model or a lower effort answers sooner. Workers do the actual work in your repositories: a larger model and a higher effort pay off there. "Default" keeps Claude Code's own choice. Models and effort levels

Passed as --model and --effort by scripts/start-controller.sh.

Claude in Chrome works only while someone is signed in at this computer's desktop, or in a remote desktop session that stays when you disconnect, with Chrome open and the Claude extension signed in to the same claude.ai account; otherwise the controller's browser tools answer that the extension is not connected. Keep a Chrome window of your own open, not only the one Claude opens for its tab group: if Claude Code closes the last window or tab, Chrome quits, and the browser tools stop until someone starts it again at the desktop. The confine hook lets them through only at the level unrestricted.

Security risk: the controller can use every login of that Chrome profile, and a password manager in it. Use a profile only for Claude: README, "Claude in Chrome".

Every worker run gets them, on this computer and in Docker.

4. Telegram optional

Approval requests reach your phone at once, also at night, questions once voice mode has ended, and /stop locks the kill switch. The PIN to unlock it in voice mode comes here too, so that you need not reach the computer from the car. Create a bot: in Telegram, write /newbot to @BotFather (how) and copy the token it gives you.

Then open your bot in Telegram, tap Start and send any message, for example "Hallo".

Unticked, a saved bot token and chat ID are deleted when you write the setup.

After this long without a voice call, voice mode counts as ended, and questions also go to Telegram. Approval requests go there at once, as Claude Code waits on them. Results wait for the next voice call. Default 600: gaps of a few minutes are normal while you talk.

Off by default: Telegram then only carries messages to you, and takes commands such as /stop. Ticked, a Reply to a question there answers it, and any other message you write to the bot reaches the controller as a request of yours, as one by voice does; its replies come back to the chat. Only messages from your own account, in your private chat with the bot, count: groups, other senders and bots are ignored, forwarded and edited messages refused, and every message is kept in .state/telegram-input.log. Push, merge, restart and delete count there as by voice, and approval requests can be answered there with a yes or a no, unless you keep them with your voice below. Whoever is signed in to your Telegram account can then do what your voice can: turn on two-step verification there, and end sessions you do not know (README 5.8).

A Reply to a question there, or a message that starts with its code, such as "8cep yes", reaches the controller as your answer, as one by voice does.

Any other message you write to the bot reaches the controller as a request of yours, and its replies come back as replies to your message.

On, an answer or a request there confirms these as the same words spoken do, and an approval request there is answered with its buttons (Yes, No, and Yes to all while several are open), or typed: yes or no as a Reply, or as a plain message while it is the only one open; "yes to all" allows every one open, and "yes 20" allows one and all such writes for 20 minutes where it offers that. Off, they take your voice: such an answer there is not carried out, the requests come without buttons, and the chat says it must be confirmed by voice.

5. Workers in Docker optional

The workers run in a container that sees only one folder of clones, with the access the GitHub token gives them.

Its name, for example voice-workers.

Mounted as /repos. Not your own checkouts: git on this computer never runs in it.

Built from docker/ for your user id.

Claude Code's login in the container

On this computer run claude setup-token, sign in, and paste the long-lived token it prints (it starts with sk-ant-). The work folders' container (section 6) uses it too. About setup-token

GitHub token: it sets what workers may do

  • read-only, nothing leaves the container: no token for public repositories; for private ones a fine-grained token with only the chosen repositories and Contents: Read-only. Not a classic token: its repo scope can also write.
  • pr, pull requests: a fine-grained token with Contents and Pull requests: Read and write (Workflows only if workers should change workflow files), and the default branch protected by a ruleset that requires pull requests, with an empty bypass list. A classic token with repo works too, for all your repositories at once.
  • full, a direct push when you ask: the same token, and a default branch without such protection.

About personal access tokens. An organisation may have to approve a fine-grained token first.

Repositories in the container

They are cloned inside the container, over HTTPS. Already in the folder: none.

Forcing a lower level than the token allows is a rule for the workers, not a limit of the token.

7. Keeping the controller running

  

    scripts/start-controller.sh runs the controller under a watchdog that starts it again after a
    crash, in a tmux session. Before it starts the controller, the setup marks the controller folder as trusted in
    Claude Code's config, and the start script does so before every start, so that Claude Code does not ask at the
    terminal whether you trust it. Section 10 says when the controller waits at the terminal all the same.
  

  

    On Linux the autostart also turns on lingering for your user (loginctl enable-linger):
    without it, systemd starts the service only at a login and stops it after the last one, an SSH
    session too.
  

  

    On macOS the autostart is a LaunchAgent: launchd starts the controller when you log in, not at boot.
    With "Start it now" too, the setup loads it, which starts it at once. For a Mac that comes back by
    itself after a restart, turn on automatic login (not possible with FileVault). While the watchdog runs,
    the Mac does not go to sleep by itself; a closed laptop lid still sends it to sleep.
