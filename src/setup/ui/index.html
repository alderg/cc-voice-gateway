2. Gateway

The voice endpoint listens on 127.0.0.1 at this port; the tunnel or proxy forwards to it.

Every git repository directly in this folder gets a worker (on this computer, without Docker).

How many workers may run at once, in all repositories together: the limit that protects your subscription. Every run of a repository counts.

How many of them in one repository at once. 1, the default: one after the other. More: the first runs in the checkout, every further one in a git worktree of its own, and the controller decides per task whether it can run next to the others. Both limits apply at once in a running gateway, without a restart.

A run is stopped after this; 360 is six hours. 0: no time limit.

Ready for review, automatic reviews start at once. A draft usually gets them only once it is marked ready, and cannot be merged before.

The rare approval the controller needs is read out in the car.

Follow the controller as "Voice controller" at claude.ai/code or in the Claude app's Code tab: read along, type to it, answer its approvals. Only the controller: Remote Control connects interactive sessions, not the workers' headless runs. Needs Claude Code signed in with claude.ai here; on Team and Enterprise an Owner turns it on first. Whoever is signed in to that account can then steer the controller; typed words start no worker, only voice requests do.

Confined: it answers, hands work to the workers and reads pull request status; nothing else. The other two levels widen what a voice request can do on this computer.

What locks the gateway and stops every worker. Manual: "emergency stop" by voice, /stop on Telegram and the controller's alarm. Automatic: also fixed rules on the workers' runs, such as a push to the default branch, a write outside the repository or unusually many changes.

The public endpoint is then only up while you use it. The gateway says on Telegram when it turned the Funnel off; /funnel on or "keep alive" there turns it on again, within about two minutes. Without Telegram only at the computer: scripts/funnel.sh start.

3. Models

The controller answers by voice, so speed counts: a smaller model or a lower effort answers sooner. Workers do the actual work in your repositories: a larger model and a higher effort pay off there. "Default" keeps Claude Code's own choice. Models and effort levels

Passed as --model and --effort by scripts/start-controller.sh.

Claude in Chrome works only while someone is signed in at this computer's desktop, or in a remote desktop session that stays when you disconnect, with Chrome open and the Claude extension signed in to the same claude.ai account; otherwise the controller's browser tools answer that the extension is not connected. Keep a Chrome window of your own open, not only the one Claude opens for its tab group: if Claude Code closes the last window or tab, Chrome quits, and the browser tools stop until someone starts it again at the desktop. The confine hook lets them through only at the level unrestricted.

Security risk: the controller can use every login of that Chrome profile, and a password manager in it. Use a profile only for Claude: README, "Claude in Chrome".

Every worker run gets them, on this computer and in Docker.

4. Telegram optional

Results, questions and approvals reach your phone once voice mode has ended, and /stop locks the kill switch. Create a bot: in Telegram, write /newbot to @BotFather (how) and copy the token it gives you.

Then open your bot in Telegram, tap Start and send any message, for example "Hallo".

Unticked, a saved bot token and chat ID are deleted when you write the setup.

After this long without a voice call, voice mode counts as ended, and questions and approvals also go to Telegram. Results wait for the next voice call. Default 600: gaps of a few minutes are normal while you talk.

5. Workers in Docker optional

The workers run in a container that sees only one folder of clones, with the access the GitHub token gives them.

Its name, for example voice-workers.

Mounted as /repos. Not your own checkouts: git on this computer never runs in it.

Built from docker/ for your user id.

Claude Code's login in the container

On this computer run claude setup-token, sign in, and paste the long-lived token it prints (it starts with sk-ant-). The work folders' container (section 6) uses it too. About setup-token

GitHub token: it sets what workers may do

  • read-only, nothing leaves the container: no token for public repositories; for private ones a fine-grained token with only the chosen repositories and Contents: Read-only. Not a classic token: its repo scope can also write.
  • pr, pull requests: a fine-grained token with Contents and Pull requests: Read and write (Workflows only if workers should change workflow files), and the default branch protected by a ruleset that requires pull requests, with an empty bypass list. A classic token with repo works too, for all your repositories at once.
  • full, a direct push when you ask: the same token, and a default branch without such protection.

About personal access tokens. An organisation may have to approve a fine-grained token first.

Repositories in the container

They are cloned inside the container, over HTTPS. Already in the folder: none.

Forcing a lower level than the token allows is a rule for the workers, not a limit of the token.

7. Keeping the controller running

  

    scripts/start-controller.sh runs the controller under a watchdog that starts it again after a
    crash, in a tmux session. On its first start Claude Code asks a few questions at the terminal:
    attach with tmux attach -t voice and answer them.
  

  

    On Linux the autostart also turns on lingering for your user (loginctl enable-linger):
    without it, systemd starts the service only at a login and stops it after the last one, an SSH
    session too.
  

  

    On macOS the autostart is a LaunchAgent: launchd starts the controller when you log in, not at boot.
    With "Start it now" too, the setup loads it, which starts it at once. For a Mac that comes back by
    itself after a restart, turn on automatic login (not possible with FileVault). While the watchdog runs,
    the Mac does not go to sleep by itself; a closed laptop lid still sends it to sleep.
